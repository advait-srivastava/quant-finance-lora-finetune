# quant-finance-lora-finetune

LoRA fine-tuning of a small open-weight LLM ([Qwen2.5-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct), 4-bit) into a quantitative-finance / NSE-derivatives specialist, trained entirely on-device on Apple Silicon. Two independent training paths are implemented against the same dataset — native [MLX](https://github.com/ml-explore/mlx) LoRA and [Unsloth](https://github.com/unslothai/unsloth)'s MLX backend — so their outputs can be compared.

## Why

General-purpose instruction models answer quant-finance questions in textbook generalities. The goal here is a small model that responds with instrument-specific detail — BANKNIFTY/NIFTY mechanics, NSE market structure (TREPS, expiry conventions), and the option-pricing math (Black-Scholes, Heston, Carr-Madan FFT, SVI) — while still running fully locally on a laptop.

## Pipeline

```
papers/*.pdf  →  extract_text.py  →  chunks.json  →  generate_qa.py  →  data/{train,valid,test}.jsonl
                                                                              │
                                                        ┌─────────────────────┴─────────────────────┐
                                                        ▼                                             ▼
                                                train_mlx.py                                  train_unsloth.py
                                          (mlx_lm.lora CLI)                          (Unsloth → MLXTrainer)
                                                        │                                             │
                                                  ./fo-adapter                          fix_adapter_config.py
                                                        │                                             ▼
                                                        │                                ./fo-adapter-unsloth
                                                        └─────────────────────┬─────────────────────┘
                                                                              ▼
                                                                        test_model.py
```

1. **`extract_text.py`** — reads every PDF in `papers/` with PyMuPDF, strips excess whitespace, and splits each document into overlapping ~250-word chunks (50-word overlap), written to `chunks.json`.
2. **`generate_qa.py`** — samples 200 chunks (seeded), and for each one asks the Claude API to write 2–3 question/answer pairs grounded in that passage, producing the instruction-tuning dataset.
3. **`train_mlx.py`** — thin wrapper around `python -m mlx_lm lora`, MLX's native LoRA trainer.
4. **`train_unsloth.py`** — the same dataset trained through Unsloth's `FastLanguageModel` → `MLXTrainer` path (Unsloth dispatches to MLX rather than bitsandbytes/TRL on Apple Silicon), with the prompt masked out of the loss via `train_on_responses_only`.
5. **`fix_adapter_config.py`** — Unsloth's `save_lora_adapters()` writes its own config schema, which `mlx_lm.load()` can't read (it expects `fine_tune_type` / `num_layers` / `lora_parameters`). This patches the Unsloth-saved `adapter_config.json` in place, deriving layer count and target-module names from the saved weights, so the resulting adapter loads in plain `mlx_lm` too.
6. **`test_model.py`** — loads the base model with a given adapter and runs a fixed set of quant-finance questions to spot-check output quality.

## Dataset

`data/` holds the resulting instruction-tuning set — 452 train / 57 validation / 57 test examples, each a single-turn `{"messages": [...]}` chat record generated by Claude from the source material. Topics span:

- Option-pricing models: Black-Scholes, Heston (correlation/skew), Carr-Madan FFT, SVI vol surface
- NSE-specific mechanics: BANKNIFTY/NIFTY expiry dynamics, TREPS overnight repo
- Risk: VaR, gamma risk on expiry, variance risk premium
- Simulation: GBM discretization for Monte Carlo paths

**Source PDFs and the raw extracted `chunks.json` are intentionally not included in this repo** — several are copyrighted texts (a standard derivatives textbook among them) used for personal study, and only the *questions and answers synthesized from them* are redistributed here, not the source text itself. To reproduce from scratch, drop your own PDFs in `papers/` and run the pipeline below.

## Two training paths

| | `train_mlx.py` | `train_unsloth.py` |
|---|---|---|
| Trainer | `mlx_lm.lora` CLI | Unsloth `FastLanguageModel` → MLX `MLXTrainer` |
| LoRA rank / alpha | 8 / (mlx_lm default scale 20.0) | 16 / 16 |
| Trained layers | last 8 transformer layers | attention + MLP modules, all layers |
| Loss masking | prompt not masked | prompt masked (`train_on_responses_only`) |
| Schedule | fixed iters (500), constant LR | 2 epochs, linear decay with warmup |
| Output | `./fo-adapter` | `./fo-adapter-unsloth` (needs `fix_adapter_config.py` before `mlx_lm` can load it) |

A reference Unsloth run (Qwen2.5-3B-Instruct-4bit, 2 epochs, effective batch size 4, 640-token max sequence length) on Apple Silicon unified memory (peak ~4 GB):


### Sample output

From `unsloth_test.log`, a held-out question (not in the training set):

> **Q: Explain gamma risk for a short BANKNIFTY straddle on expiry day.**
> A: Gamma risk is the first-order derivative of the option price with respect to the underlying price... On expiry day, for a BANKNIFTY short straddle, gamma is negative and highly unstable. The stock price on expiry day can move sharply, triggering simultaneous option calls and puts to be exercised, causing gamma to spike dramatically... Risk analysts must monitor gamma netting on expiry days, as unnetted short gamma positions can lose 50-100% of notional value in a tightly-structured BANKNIFTY expiry session.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install mlx mlx-lm anthropic pymupdf safetensors
# for the Unsloth path:
pip install unsloth unsloth_zoo datasets
```

Tested with `mlx-lm 0.31.3`, `mlx 0.31.2`, `unsloth 2026.5.7` on Apple Silicon.

`generate_qa.py` calls the Anthropic API and expects `ANTHROPIC_API_KEY` in the environment.

## Usage

```bash
# 1. Extract + chunk your own source PDFs
python extract_text.py            # papers/*.pdf -> chunks.json

# 2. Synthesize the QA dataset
export ANTHROPIC_API_KEY=sk-...
python generate_qa.py             # chunks.json -> data/{train,valid,test}.jsonl (split not included here — see script)

# 3a. Train with native MLX LoRA
python -m mlx_lm lora \
  --model mlx-community/Qwen2.5-3B-Instruct-4bit \
  --data ./data --train \
  --batch-size 1 --num-layers 8 --iters 500 \
  --learning-rate 1e-5 --adapter-path ./fo-adapter --seed 42

# 3b. …or train with Unsloth on MLX
python train_unsloth.py
python fix_adapter_config.py ./fo-adapter-unsloth

# 4. Try it
python test_model.py                                   # uses ./fo-adapter
ADAPTER_PATH=./fo-adapter-unsloth python test_model.py  # uses the Unsloth adapter
```

> **Note:** `train_mlx.py` predates a flag rename in `mlx_lm` (it still passes `--lora-layers`, current `mlx_lm.lora` expects `--num-layers`) — use the CLI invocation above directly rather than the wrapper script until it's updated.

## Repo structure

```
extract_text.py         PDF -> chunked text
generate_qa.py           chunks -> Claude-generated QA pairs
train_mlx.py              mlx_lm.lora wrapper (see note above on the stale flag)
train_unsloth.py          Unsloth/MLXTrainer training loop
fix_adapter_config.py     patches an Unsloth adapter to load in mlx_lm
test_model.py             qualitative eval against a fixed question set
data/                     train.jsonl / valid.jsonl / test.jsonl (452/57/57 examples)
```

Not tracked in this repo (see `.gitignore`): `papers/` and `chunks.json` (copyrighted source material), and every trained adapter/checkpoint directory (`fo-adapter/`, `fo-adapter-unsloth/`, `outputs-unsloth*/` — regenerate with the commands above rather than committing multi-hundred-MB binaries).
